# Financial Gateway — Medallion Lakehouse & Time Travel

## Overview

Project 14b models a payment gateway using Snowflake's Bronze, Silver, and Gold layers. Raw payment JSON is transformed into cleaned transactions with masked card numbers, processing fees, and net settlement amounts, then aggregated into merchant settlement metrics.

The project also simulates status corruption, uses Snowflake Time Travel to inspect the prior state, restores the affected records, and reconciles totals across layers.

## Concepts Demonstrated

- Bronze/Silver/Gold medallion architecture
- Snowflake `VARIANT` JSON ingestion
- Fee and net settlement calculations
- Credit-card masking to last four digits
- Approved-transaction merchant aggregation
- Time Travel with `BEFORE (STATEMENT => ...)`
- Recovery using historical transaction state
- Cross-layer reconciliation auditing

## Project Structure

```text
Project 14b/
├── JSON_FILES/
│   └── bronze_payment_payloads.json
├── Project-14b.txt
├── Project_14b.sql
└── README.md
```

`Project_14b.sql` creates the Snowflake context, loads Bronze payment payloads, builds Silver and Gold tables, performs Time Travel inspection and recovery, and runs reconciliation. `Project-14b.txt` documents the scenario and expected outputs.

## How to Run

1. Make `bronze_payment_payloads.json` available through `P14B_STAGE`.
2. Use a Snowflake role that can create `P14B_WH`, `P14B_DB`, `P14B_SCHEMA`, stages, tables, and run Time Travel queries.
3. Execute `Project_14b.sql` from top to bottom so the historical inspection and recovery use the statement ID generated by the scripted update.
